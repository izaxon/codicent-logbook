Commands

A handful of verbs.

Every command is a plain shell call — easy for people, trivial for agents. Run logbook, logbook data or logbook chat for full help.

Entries
initaddgetlistfindhistorystatus

Tags come from #markers in the text or -t a,b. --amend <id> writes a new version; list shows only the latest, newest first, with --from/--to and --start/--length.

Data messages
data setdata getdata amenddata hidedata import

JSON key-value records with --filter k=v, --format entry|json|csv|table|export and idempotent export → import between instances.

Remote & chat
loginlogoutchat listchat export

Device-flow login stores a .logbook-session in the current folder; every command then runs against that Codicent project instead of local files.

Everyday use · entries 
logbook add "Deployed 1.12.2 to prod #deploy #prod"
echo "long notes…" | logbook add -t notes
logbook add -t deploy --amend <id> "Deployed 1.12.3"
logbook list -t deploy --from 2026-10-01
logbook find --body-only "rollback"
logbook history <id>
Structured records · data messages 
logbook data set -t customer '{"name":"Acme","status":"active"}'
logbook data get -t customer --filter status=active
logbook data get -t customer --format table
logbook data get -t customer --format export --all \
  --output customers.json
logbook data import customers.json --dry-run
On disk

Files you can read without the tool.

Entries are never rewritten or deleted. Tags are folders of links, superseded versions are marked — so plain grep, ls and git log keep working.

An entry · Markdown + YAML
---
id: 3f2a1b4c-…
created_utc: 2026-10-25T13:15:41Z
tags: [agent, memory]
parent_id: 9b7e…     # previous version
original_id: 9b7e…   # chain root
---

User confirmed they prefer dark mode in all apps.
The data folder · LOGBOOK_ROOT
data/
├── entries/YYYY/MM/DD/<ts>__<id>.md
│     # immutable entry files
├── tags/<tag>/<ts>__<id>.md
│     # links into entries/
└── superseded/<id>
      # marker: a newer version exists

On Windows without Developer Mode, tag links fall back to file copies — queries behave the same.

For AI agents

Persistent memory is one shell call away.

Agents forget between sessions. Any agent that can run a command — Claude Code, Codex, OpenClaw, a cron script — can write decisions down and recall them later. No API, no auth, no SDK.

Agent instructions · CLAUDE.md / AGENTS.md 
## Memory
Use the `logbook` CLI as persistent memory.
- Recall first: `logbook list -t memory --length 20`
  or `logbook find -t memory "<topic>"`
- Record decisions: `logbook add "<fact> #memory #<topic>"`
- Correct a fact: `logbook add --amend <id> -t memory "<new>"`
- Never edit files under data/ by hand.
OpenClaw · shell tool 
tools:
  - name: logbook
    type: shell
    description: Persistent memory log. Immutable, tagged, versioned.
    commands:
      add:     "logbook add -t {tags} {message}"
      list:    "logbook list -t {tags}"
      find:    "logbook find -t {tags} {pattern}"
      get:     "logbook get {id}"
      history: "logbook history {id}"
Need MCP instead of shell calls (Claude Desktop, Cursor)? That's the Logbook server — same model, served over MCP and OpenAPI.
Remote backend

Same commands, shared project.

Log in once and the CLI stores entries in a Codicent project instead of local files — so a team, or several agents on different machines, share one log. Entries become Codicent messages; data commands map to #data messages.

Interactive · device-flow login 
logbook login                       # codicent.com, project "logbook"
logbook login --url https://myserver.com --project myproj
logbook status                      # mode, URL, project, expiry
logbook add "Shared note #team"
logbook logout
CI & automation · environment 
export LOGBOOK_REMOTE_URL="https://codicent.com"
export LOGBOOK_REMOTE_TOKEN="<api-token>"
export LOGBOOK_PROJECT="myproject"
logbook data get -t customer --format json
# env vars win over .logbook-session

Remote mode searches full message content only — --body-only/--meta-only are local-mode features.

Configuration

A few environment variables.

Nothing to configure for local use: the CLI walks up from the current folder to find data/entries/, like git finds .git.

VariableDefaultDescription
LOGBOOK_ROOT(nearest folder with data/entries/, else cwd)Where the local log lives.
LOGBOOK_REMOTE_URL(none)Codicent base URL; with a token, switches every command to remote mode.
LOGBOOK_REMOTE_TOKEN(none)Bearer token for the remote project.
LOGBOOK_PROJECT(none)Remote project name.
LOGBOOK_VERSION(newest)Install scripts only: pin a CLI version, e.g. 0.8.0.
